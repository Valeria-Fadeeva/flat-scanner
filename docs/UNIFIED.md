# 3. ВХОДНЫЕ ДАННЫЕ (SANE API)

## Интерфейс захвата

* Старт строго по триггеру оператора (кнопка во Flutter), не автономно.
* Системный вызов `scanimage` из Rust через `std::process::Command`:
  * Разрешение: **300 DPI**
  * Формат: несжатый RAW/TIFF (исключает артефакты компрессии перед CV-анализом)
  * Область: полный кадр планшета A3 (или А4 при обнаружении Canon LiDE/genesys/pixma)

## Автоопределение геометрии устройства

При обнаружении в имени SANE-устройства строк `"genesys"`, `"pixma"` или `"niash"` автоматически переключается профиль на A4 (210×297 мм). Иначе используется полный A3 (297×420 мм).

## Матрица внешних паразитных помех

Алгоритмы обязаны программно вырезать:
* Элементы интерьера помещения (потолок, лампы дневного света)
* Блики от освещения на глянцевых элементах страниц
* Тени рук оператора при удержании книги

> ⚠️ **Коллизия А:** При захвате полного кадра A3 @ 300 DPI получается растр ~3300×4700 px (~45 MB RGB несжатое). Передача такого буфера во Flutter требует Zero-Copy обёртки или превью JPEG/WebP — иначе фриз UI-изолята на 300–450 мс.

# 4. COMPUTER VISION КОНВЕЙЕР (Rust ядро)

## 4.1 Сегментация макрообъектов (Поиск книги)

Книга — «самый большой контрастный объект» на фоне зашумлённого потолка.

Пайплайн:
1. Преобразование в градации серого (`cvtColor`)
2. Размытие Гаусса σ=7×7 для подавления мелкого шума ламп
3. Детектор границ Кэнни с широким окном [50; 150]
4. Поиск самого крупного замкнутого контура → всё вне него обрезается и отправляется в Drop

> ❌ НЕ РЕАЛИЗОВАНО: Грубая маска Otsu/Gaussian blur до детекции Хафа для изоляции зоны книги от текстуры потолка/ламп. Требуется добавить.

## 4.2 Изоляция боковых артефактов ("Боковушек")

**Проблема:** Торцы предыдущих/последующих страниц толстых книг создают ложные параллельные линии контуров.

**Решение:** Анализ градиента плотности по краям макроконтура — истинная страница монолитна (белая/серая подложка), а "боковушка" представляет каскад частых чередующихся тёмных и светлых линий слоёв бумаги. Обнаружение паттерна → принудительный сдвиг рамки внутрь на шаг дефекта.

> ❌ НЕ РЕАЛИЗОВАНО.

## 4.3 Алгоритм детекции четырёх вершин ✅ Реализован

Детекция использует двухэтапную стратегию: первично HoughLinesP + кластеризацию углов, fallback — findContours + аппроксимация.

### Первичный метод: HoughLinesP + кластеризация

1. Выделение протяжённых линейных сегментов через `HoughLinesP` (ρ=1.0, θ=π/180, threshold=80, minLen=50, maxGap=10).
2. Кластеризация отрезков по углу наклона в четыре группы:
   * **top_lines**: горизонтальные (~0° или ~180°), mid_y < src.rows()/2
   * **bottom_lines**: горизонтальные, mid_y ≥ src.rows()/2
   * **left_lines**: вертикальные (~65–115°), mid_x < src.cols()/2
   * **right_lines**: вертикальные, mid_x ≥ src.cols()/2
3. Для каждого кластера вычисляется репрезентативная прямая как взвешенная медиана отрезков (вес = длина отрезка). Прямые экстраполируются за пределы изображения (scale=5000/norm) для надёжного пересечения.
4. Вершины P₁..P₄ вычисляются как точки пересечения пар прямых:
   * P₁ = top ∩ left (верхний левый угол)
   * P₂ = top ∩ right (верхний правый угол)
   * P₃ = bottom ∩ right (нижний правый угол)
   * P₄ = bottom ∩ left (нижний левый угол)

Если один из кластеров пуст или прямые параллельны (denom < 1e-6) — переход к fallback.

### Fallback: findContours + approxPolyDP / minAreaRect

1. Бинаризация Otsu (`THRESH_BINARY_INV + THRESH_OTSU`)
2. Поиск контуров (`RETR_EXTERNAL`, `CHAIN_APPROX_SIMPLE`)
3. Выбор самого крупного контура по площади (минимум 1% от площади кадра)
4. Аппроксимация многоугольником `approxPolyDP(ε = perimeter × 0.02)`
5. Если получено ровно 4 вершины → сортировка TL→TR→BR→BL и возврат результата
6. Иначе: `minAreaRect` на лучшем контуре → 4 угла прямоугольника → сортировка

Сортировка четырёх точек: упорядочивание по сумме x+y (диагональная проекция), затем разделение на верхнюю/нижнюю пары и сортировка внутри каждой пары по X.

> ⚠️ **Коллизия Б:** При открытой крышке текстура потолка может давать ложные линии Хафа длиннее истинных краёв бумаги. Требуется coarse_masking до детекции Хафа согласно docs/проверить.md.

## 4.4 Устранение деформаций корешка (Деварпинг / De-warping)

**Проблема:** Книги с тугим корешком имеют жёсткий изгиб в центре разворота. Текст уходит вглубь, строки искривляются дугой.

**Решение — кусочно-линейная/цилиндрическая трансформация:**
1. Детекция центральной линии изгиба по градиенту плотности тени корешка
2. Построение адаптивной Mesh Grid на основе анализа искривления базовых строк текста (Text Line Tracking)
3. Применение обратной координатной трансформации `remap` для выпрямления строк на плоскости

> ❌ НЕ РЕАЛИЗОВАНО. Требуется отдельный модуль `src/cv/warping.rs`.

# 5. ОБРАБОТКА ИЗОБРАЖЕНИЙ И БИНАРИЗАЦИЯ

## Поканальная фильтрация

Системный фильтр обрабатывает изображение в трёх независимых режимах:

| Профиль | Описание | Формат |
|---------|----------|--------|
| Текст | Монохромное бинарное изображение | 1-bit B/W |
| Иллюстрация/Фото | Полутоновое сероградационное | 8-bit Grayscale |
| Цвет | Обложки, цветные вкладки | 24-bit RGB |

## Адаптивная бинаризация старой бумаги (Sauvola Threshold)

Стандартный фиксированный порог стирает бледный текст у корешка или превращает фон старых книг в шум. Решение — алгоритм Сауволы со скользящим окном:

```math
T(x, y) = m(x, y) * [1 + k * (s(x, y) / R - 1)]
```

Где:
* `m(x,y)` — локальное среднее значение яркости через box_filter(window_size × window_size)
* `s(x,y)` — стандартное отклонение внутри окна
* `R` — динамический диапазон серого (~128 для 8-bit изображения)
* `k` — коэффициент чувствительности (рекомендовано 0.2–0.6; ТЗ предлагает ручную калибровку оператором: 70 / 80 / 90 / 110 единиц смещения)

Пакетная регулировка подложки гарантирует выжигание жёлтого фона до чисто белого (#FFFFFF) с сохранением штрихов букв.

### Реализация (`cv/binarization.rs`) ✅ Полностью готова

Функция `apply_sauvola_threshold(src, k, window_size)` корректно реализует формулу через поканальные операции OpenCV с раздельными буферами для избежания aliasing эффектов. Использует `CMP_LT` для получения чёрного текста на белом фоне.

## Сохранение печатей и штампов

Алгоритм обязан дифференцировать текст и библиотечные штампы/печати. Синяя или красная печать изолируется в отдельном цветовом канале (например, инвертированный канал Cr в пространстве YCbCr), очищается от шума бумаги и накладывается поверх бинаризированного текстового слоя.

# 6. PDF И СЖАТИЕ CCITT GROUP 4

## Пакетный дебаг готовых документов

Программа должна уметь открывать существующие «чужие» PDF:
* Замена испорченных страниц
* Внедрение пропущенных листов
* Очистка от шума сторонних сканов

Конвейер разборки: векторный текст отделяется от графической подложки, страницы экспортируются как растровые слои для точечной замены.

## 1-битное сжатие CCITT T.6 Group 4

Экспортный модуль упаковывает бинаризированные текстовые страницы строго по стандарту **CCITT Group 4**:
* Кодирует длину серий одинаковых цветов по двумерной схеме отношений
* Вес одной ЧБ-страницы A3 падает до ~80–120 KB при идеальной резкости букв
* Книга из 400 страниц весит ≤ 40 MB итогового PDF

> ❌ НЕ РЕАЛИЗОВАНО. Сейчас сохраняется только PNG через `imwrite`. Требуется подключить крейт `tiff` или прямой вызов libtiff для CCITT G4 энкодинга.

# 8. ОТКАЗОУСТОЙЧИВОСТЬ И УПРАВЛЕНИЕ СЕССИЯМИ

## Локальное кэширование SQLite / Isar DB

Архитектура «Нулевой потери рантайма»:
* Каждому проекту присваивается уникальный UUID книги.
* Для каждого разворота атомарно записываются: абсолютный путь к сырому файлу, массив из 8 координат вершин [4 левых + 4 правых], выбранный порог трэшхолда, текущий статус обработки.

## Горячий рестарт сессии

При перезапуске программы после сбоя система считывает последний незавершённый UUID из БД, восстанавливает очередь и открывает книгу ровно на той странице, где процесс был прерван.

Произвольная навигация по книге:
* Возврат к любой ранее обработанной странице для пересъёмки
* Вставка пропущенных листов с автоматическим сдвигом нумерации
* Удаление дефектных страниц без нарушения структуры проекта

> 🚨 **Коллизия В:** Race Condition при горячем рестарте — если питание пропадает во время записи координат в Isar/SQLite, база может повредить индекс книги. Требуется journal_mode=WAL+checkpoint перед критичными секциями или двойное журналирование (`/tmp/<uuid>.pending` → подтверждение → коммит).

> ❌ НЕ РЕАЛИЗОВАНО полностью. Требуется внедрить SQLite/Isar слой.
